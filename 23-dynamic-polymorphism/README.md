# Занятие 23. Динамический полиморфизм: `dyn Trait` и `dyn Any`

Примеры построены на PDF и LIVE-коде из архива `dispatch`.

## Trait-объекты и динамическая диспетчеризация

- `Drawable` задаёт общий интерфейс для разных типов;
- `Rect` и `Circle` по-разному реализуют `shape_name` и `draw`;
- `DynCanvas` хранит гетерогенную коллекцию `Vec<Box<dyn Drawable>>`;
- метод `add` упаковывает конкретное значение в `Box`;
- `draw_shape` принимает `T: Drawable + ?Sized`, поэтому работает и с конкретными типами, и с trait-объектами;
- `describe_borrowed` показывает использование `&dyn Drawable` без передачи владения.

Вызов метода через `dyn Drawable` выполняется по vtable: конкретный тип значения не нужен в сигнатуре коллекции.

## Диспетчеризация через перечисление

LIVE-архив также содержит вариант с crate `enum_dispatch`. Здесь тот же пример реализован вручную и без внешних зависимостей:

- `Shape` содержит варианты `Rect` и `Circle`;
- реализация `Drawable for Shape` перенаправляет вызовы через `match`;
- `From<Rect>` и `From<Circle>` позволяют добавлять фигуры через `Into<Shape>`;
- `EnumCanvas::draw_shape` использует обобщённый параметр и статическую диспетчеризацию.

В отличие от `Box<dyn Drawable>`, перечисление заранее перечисляет все поддерживаемые варианты.

## `Any`, `TypeId` и downcast

- `demo_values` создаёт `Vec<Box<dyn Any>>` из `u32`, `f32` и `String`;
- `describe` восстанавливает конкретный тип через `downcast_ref`;
- неподходящий `downcast_ref` возвращает `None`, а не паникует;
- `same_type` сравнивает типы через `TypeId::of`.

`Any` применяется для типов со временем жизни `'static` и позволяет безопасно проверить конкретный тип значения за trait-объектом.
