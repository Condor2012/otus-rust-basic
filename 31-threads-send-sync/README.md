# Занятие 31. Потоки, `Send + Sync` и каналы

Примеры построены на презентации, включая код, размещённый на слайдах-изображениях. Используется только стандартная библиотека Rust.

## Interior mutability и `RefCell`

- `RefCell<String>` позволяет заменить строку через `borrow_mut`, имея разделяемую ссылку на сам `RefCell`;
- это однопоточный механизм: `RefCell<T>` не реализует `Sync`, поэтому `&RefCell<T>` нельзя безопасно передавать в `thread::spawn`;
- ошибочный пример со слайдов не включён как компилируемый код, рабочий пример остаётся в одном потоке.

## Создание потоков и ссылки

- `thread::spawn` принимает `FnOnce() -> T`, а `JoinHandle::join` возвращает результат потока;
- `spawn_and_join` передаёт в поток замыкание и получает `42`;
- обычный `spawn` требует `'static`, поэтому не может заимствовать локальную `String` без гарантий времени жизни;
- `thread::scope` гарантирует завершение вложенных потоков до выхода из области и позволяет разделять `&String`;
- `Arc<String>` и замыкание `move` дают владеющему потоку собственную ссылку на общие данные.

## `Send` и `Sync`

- `T: Send` означает возможность передать значение в другой поток;
- `T: Sync` означает возможность разделять `&T` между потоками;
- обобщённые функции `assert_send` и `assert_send_sync` проверяют ограничения на этапе компиляции;
- `String` и `RefCell<String>` реализуют `Send`;
- `Arc<String>`, `AtomicUsize`, `Mutex<String>` и `RwLock<String>` реализуют `Send + Sync`;
- ручные unsafe-реализации маркерных трейтов не используются.

## Синхронизация

- `AtomicUsize` атомарно увеличивает общий счётчик через `fetch_add`;
- `Mutex` предоставляет исключительный доступ к изменяемому счётчику;
- `RwLock` демонстрирует эксклюзивную запись и разделяемое чтение;
- `Barrier` синхронизирует два потока в общей точке;
- все потоки завершаются через `join`, поэтому тесты детерминированы.

## Каналы MPSC

- `mpsc::channel` передаёт владеющие значения между потоками без блокировки отправителя при заполнении фиксированного буфера, поскольку такого буфера нет;
- `mpsc::sync_channel(2)` имеет ограниченный буфер и блокирует отправителя, когда он заполнен;
- клонирование `Sender` показывает модель Multi-Producer-Single-Consumer;
- после уничтожения отправителей итерация `Receiver` завершается;
- бесконечные циклы со слайдов заменены конечной отправкой трёх значений.
