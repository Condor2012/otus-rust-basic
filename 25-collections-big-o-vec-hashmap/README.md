# Занятие 25. Коллекции, Big O, `Vec<T>` и `HashMap<K, V>`

Примеры соответствуют презентации занятия и используют только стандартную библиотеку Rust.

## Big O

Модуль `complexity` демонстрирует сложности из слайдов:

| Сложность | Пример |
|---|---|
| `O(1)` | получение первого элемента среза |
| `O(log n)` | бинарный поиск в отсортированном срезе |
| `O(n)` | линейный поиск |
| `O(n log n)` | сортировка копии через `sort_unstable` |
| `O(n²)` | построение всех пар вложенными циклами |

`O(2ⁿ)` в презентации дано как справочный класс сложности и отдельно не реализовано.

## Вектор `Vec<T>`

- создание через `Vec::new` с последовательными `push`;
- создание макросом `vec![1, 2, 3]`;
- предварительное выделение памяти через `Vec::with_capacity(1024)`;
- `clear` удаляет элементы, но сохраняет ёмкость;
- работа как со стеком через `push` и `pop`;
- `insert` и `remove` сохраняют порядок остальных элементов;
- `swap_remove` удаляет элемент без сохранения порядка;
- сортировка через `sort_unstable`.

Псевдокод внутреннего устройства `Vec` со слайдов не воспроизведён через `unsafe`: примеры используют безопасный публичный API.

## Хэш-карта `HashMap<K, V>`

- создание с начальной ёмкостью через `HashMap::with_capacity`;
- `insert` добавляет пару и заменяет значение существующего ключа;
- `entry().or_insert()` и `or_insert_with()` выполняют условную вставку;
- `get`, `get_mut` и `contains_key` обеспечивают доступ и проверку;
- `remove_entry` удаляет и возвращает пару ключ-значение;
- `len`, `is_empty`, `capacity`, `reserve`, `shrink_to_fit` и `clear` показывают информационные операции и управление ёмкостью;
- `sorted_scores` добавляет детерминированный вывод, поскольку порядок итерации `HashMap` не гарантирован.

Вариант с `FnvBuildHasher` из презентации требует внешнего crate `fnv`, поэтому здесь используется стандартный hasher `HashMap`.
