# Занятие 30. Работа с кучей: `Box`, `Rc`, `Arc` и RAII

Примеры соответствуют PDF занятия и используют только стандартную библиотеку Rust.

## RAII и `Drop`

- `Resource` представляет владеющий ресурсом объект;
- `Drop::drop` автоматически вызывается при выходе владельца из области видимости;
- в тестах счётчик показывает освобождение двух ресурсов после области видимости;
- `drop(resource)` позволяет освободить ресурс явно и досрочно.

Тот же принцип используется для памяти, файлов, сокетов и блокировок.

## `Box<T>` и другие формы `Box`

- `boxed_value` размещает одно значение в куче, а оператор `*` выполняет разыменование;
- `boxed_slice` создаёт `Box<[i32]>` — владеющий срез фиксированной длины без `capacity` как у `Vec`;
- `boxed_trait` создаёт `Box<dyn Number>` с динамической диспетчеризацией;
- рекурсивный `List::Cons(i32, Box<List>)` имеет конечный размер, поскольку следующий элемент хранится за указателем;
- при выходе `Box` из области видимости его содержимое уничтожается автоматически.

`Box::into_raw`, `Box::from_raw` и `Box::leak` упомянуты в PDF, но здесь не используются: первые два требуют осторожной работы с сырыми указателями, а последний намеренно не освобождает память.

## `Rc<T>`

- `Rc::clone` создаёт ещё одного владельца, а не копию содержимого;
- `Rc::strong_count` показывает увеличение счётчика при клонировании и уменьшение после `drop`;
- `Rc::downgrade` создаёт слабую ссылку;
- `Weak::upgrade` возвращает `Some`, пока есть сильный владелец, и `None` после уничтожения значения.

`Rc` использует неатомарный счётчик и предназначен для одного потока.

## `Arc<T>`

- `Arc` разделяет одни данные между двумя потоками через клонирование умного указателя;
- после завершения потоков остаётся один сильный владелец;
- слабые ссылки `Arc::downgrade` и `Weak::upgrade` работают аналогично `Rc`;
- атомарный счётчик делает `Arc` пригодным для многопоточного разделения данных.

Слабые ссылки не увеличивают сильный счётчик и помогают избегать циклических ссылок.
